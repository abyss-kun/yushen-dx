# 「重新加载界面」方案与下线记录

> 2026-11-09 老板：记个方案，然后删掉吧，没有用会报错。

## 原来做的

后台页面右上角一个「重新加载界面」按钮：

```js
h('button', {
  onClick: function () { try { location.reload() } catch {} },
}, '重新加载界面')
```

目的：DSH 打包版没有 Ctrl+R / F5（Electron 没注册刷新快捷键），改了客户端代码后想不重启宿主就生效。

## 为什么删

`location.reload()` 在 DSH 里不是"只刷新页面"——它会**重新走一遍 web boot**，把**所有 client 插件重新 import**。

后果：

1. 如果那一刻某个插件加载失败（例如 `dsh-yushen-popup: import failed`），重载直接把应用带到 **「应用无法启动或已意外停止」** 的崩溃对话框；
2. 崩溃对话框只有「退出 / 重启 / 禁用第三方插件」三个选项——等于逼用户做危险操作；
3. 收益只是"省一次关窗口"，风险是"整个应用起不来"，完全不值。

**结论：Electron 应用内部不要做全局 reload 按钮。** 它会把"某一处小问题"放大成"整个应用崩溃"。

## 替代方案（以后改 client 代码怎么生效）

| 改动类型 | 生效方式 |
|---|---|
| 只改 client 代码 | 关窗口重开（页面重新加载） |
| 改 host 代码（路由/接口） | 重启宿主 |
| 以后如果 DSH 提供官方"插件热重载/安全刷新"接口 | 再接，不自己造 reload |

## 归档

按钮代码已从 `client.js` 删除（本次改动）。如果以后 DSH 支持安全的插件级重载，按官方接口重做，不回到 `location.reload()`。
