# 时间

一句话：**「现在几点」只问系统（`new Date()`）；要本地时间，只从 `lib/clock.js` 取。**

（2026-11-02 老板立：统一时间观念，用系统时间。这条是框架层的，不是某个脚本的。）

## 为什么

在这次改之前，全仓有 **41 处**手写「加 8 小时再切字符串」去假装本地时间。那不是系统时间，是把一个时区写死在代码里：

- 换台机器、改了系统时区，所有日志、文件名、账本日期一起错；
- 同一件事各处口径不一样（有的按 UTC 日算，有的按 +8 日算），两台设备合并时对不上；
- 谁也说不清哪个才是「现在写下的那一条」。

## 三条规矩

1. **禁止**在别处自己做时区加减、自己拼 `+08:00`。要本地时间 → `lib/clock.js`。
2. 时区**默认跟随系统**；要固定成别的时区，设环境变量 `YUSHEN_TZ`（例如 `Asia/Shanghai`），不写进代码。
3. 时间只用来**展示和排序参考**；跨设备「谁先谁后」看逻辑时钟 `seq`（见 `sync/merge.mjs`）。时间不是事实源。

## 函数（`lib/clock.js`）

| 函数 | 返回 | 用途 |
|---|---|---|
| `now()` | `Date` | 就是 `new Date()`，不加减 |
| `nowMs()` | 毫秒 | 原来 `Date.now()` 的地方 |
| `localISO(d = now())` | `YYYY-MM-DDTHH:mm:ss+08:00` | 本地 ISO；偏移按那一刻的真实时区算 |
| `today(d = now())` | `YYYY-MM-DD` | 本地日期 |
| `dayKey(ms)` | `YYYY-MM-DD` | 兼容老调用 |
| `todayIn(tz, d)` | `YYYY-MM-DD` | 指定时区（只给「对端口径」用） |
| `fmt(d, 'HH:mm')` | 字符串 | 模板：`YYYY` `MM` `DD` `HH` `mm` `ss` |
| `fmtFull(d = now())` | `YYYY-MM-DD HH:mm:ss` | 账本/日志最常用那一行 |
| `zone()` | 时区名 | 现在生效的时区（系统或 `YUSHEN_TZ`） |

旧写法 → 新写法：

| 以前 | 现在 |
|---|---|
| `new Date(Date.now() + 8 * 3600e3).toISOString().replace('Z', '+08:00')` | `localISO()` |
| `…toISOString().slice(0, 10)` | `today()` / `dayKey(ms)` |
| `…toISOString().slice(0, 19).replace('T', ' ')` | `fmtFull(d)` |
| `…slice(0, 16).replace('T', ' ')` | `fmt(d, 'YYYY-MM-DD HH:mm')` |
| 文案里写死 `（Asia/Shanghai）` | `（${zone()}）` |

## 系统时区不是东八区怎么办

默认不会错——只跟着系统走。想让显示固定成北京时间，就设 `YUSHEN_TZ`：

```powershell
$env:YUSHEN_TZ = 'Asia/Shanghai'          # 当前窗口
[Environment]::SetEnvironmentVariable('YUSHEN_TZ', 'Asia/Shanghai', 'User')   # 以后都生效
```

服务器设成 UTC、又想跟老板对同一段时间，也用它；**别去改代码里的偏移**。

## 故意不是系统时间的几处（别一刀切）

1. **`sync/` 的 `seq` 与水位**：逻辑时钟，跟墙上时间无关。合并只认 `(device, seq)`；时间只用来展示和排序参考。
2. **`lib/peak.js` 的北京时间**：峰时/谷时是**计价口径**（官方按北京时间），不是「现在几点」。这是业务规则，跟随系统反而错。
3. **`lib/bili-inbox.js` 的 `BILI_ZONE`**：B站 拉取脚本按 +8 命名文件（对端口径）。要改先改对端（python），只改这一头会读不到当天的文件。
4. **历史时间点的解析**（`RULE_SINCE`、`Date.parse('…+08:00')`、测试里的 `NOW`）：那是把一个**确定的时刻**写下来，不是取「现在」。
5. **回归/演练里写死的时间**：造场景必须固定，跟随系统就没法断言了。

## 还欠的一笔（已记账，没在这次改）

`lib/` 里还有十几处 `toISOString().slice(0, 10)` 拿「今天」用（UTC 日）。它们自身是自洽的，但**日界在本地 08:00 而不是 00:00**（每日配额、去重、冷档都按这个日切）。
改成系统日会移动日界，属于改变行为，所以单独决策，不混在「只换时间来源」这一次里。

## 机器判据

`node scripts/regression.mjs` 里有三条：

- 全仓扫 `8 * 3600e3` / `8 * 3600 * 1000`，**命中 0**；
- `lib/clock.js` 导出齐全、`localISO()` 的偏移等于系统时区、`YUSHEN_TZ` 能覆盖、文件里没写死时区名；
- 本文存在且提到 `lib/clock.js`、`禁止`、`seq`、`YUSHEN_TZ`。
