# 图书馆架构：照着真图书馆做

> 2026-11-04 老板：「图书馆是很大的，有不同的大区、不同的小区，小区里还有很多书架，书架之间不一样，
> 书与书之间也可能不一样……要不要查查图书馆的架构、管理方式、怎么分区分类，他们还有一套电脑分区方式。」
>
> 查了，学了三样：**索书号怎么组**、**馆藏怎么分三线**、**电脑里怎么记**。

## 一、真图书馆怎么干（查到的）

**分类**：中国多数高校馆用《中图法》，**22 个基本大类**（A 马列、B 哲学、C 社科总论、D 政治法律、E 军事、F 经济、G 文化教育、H 语言文字、I 文学、J 艺术、K 历史地理、N 自科总论、O 数理、P 天文地球、Q 生物、R 医药、S 农业、T 工业技术、U 交通、V 航空、X 环境、Z 综合）。
大类下**逐级展开**（例：TP → TP3 → TP31 → TP316 → TP316.81，越往后越专指）。

**索书号 = 分类号 + 著者号**（还有复分号、卷次、版次）。
- 分类号解决"同一类聚在一起"；
- 著者号解决"同类不同人的书怎么排"（《数学分析》O17/169 与 O17/871）；
- 复分号挂在后面：`TP3-61`（-61 词典）、`-4` 教育、`-43` 教材、`-62` 手册。

**排架规则**：先按分类号从小到大，相同再按著者号；书脊贴索书号。期刊按"分类号+刊名字顺号"，同种再按卷期。

**馆藏分三线**：一线**开架**（随手可取）→ 二线**闭架**（找管理员）→ 三线**密集/储备**（很少动，压缩存放）。

**电脑里怎么记**（MARC21 通用字段）：

| 字段 | 装什么 |
|---|---|
| 001 | 控制号（系统里唯一） |
| 100 / 700 | 主要著者 / 其他著者 |
| 245 | 题名 |
| 4XX / 6XX | 丛编 / 主题词（650 论题、651 地理） |
| 084 | **分类号** |
| 852 | **馆藏地**（哪个库、哪个架位） |
| 856 | 电子地址 |

外加两个动作：**剔旧**（淘汰有规矩）、**清点**（账上有、架上在不在）。

## 三、目录怎么分层（2026-11-04 晚上补）

> 老板：「总的大纲有时候找起来很慢，还会看漏；如果知道大概在哪个区，就去找对应的区目录，范围越小越好找。」

| 层 | 文件 | 放什么 | 多大 |
|---|---|---|---|
| **总目** | `catalog/目录-总目.md` | 只有 11 个大区、张数、小区数、指针（**不列条目**） | 一眼看完 |
| **区目** | `catalog/区/<类>-<名>.md` | 这个区按「小区 → 书架」分节，列到条目 | 一个文件翻得到 |
| **小区** | **不单独出文件** | 小区在区目里分节 | 省一次"打开—返回" |

**小区为什么不再拆一层**：小区通常几到几十条，区目里一屏翻得到；再拆文件反而慢。真到某个小区几百条，再用 `library-lookup` 直接搜——那时候搜索比翻目录快。

## 四、我们的检索原理（别以为是"人找书"）

我们**没有**理解语义再去找的能力。实际是三种很笨但很快的办法：

1. **包含匹配**（`find-any`、`grep`）：给一个词逐字找。词准就快，词偏就找不到；
2. **倒排索引**（`lib/inverted.js` → `倒排.json`）：事先建"词→文件"，查时不用扫全盘；
3. **目录/卡片**（总书目）：不是搜内容，是查"这东西存在吗、在哪一区"——最像人类查目录。

**所以**：找具体内容 → 搜索（词给准）；找"有没有、在哪" → 总目/区目。

## 五、加东西之前先查（硬规矩）

```powershell
node scripts/library-lookup.mjs <你想加的东西>
```

查六处：总书目、框架文档、代码（文件名+导出）、回归断言标题、机制清单、区目录。结论三档：
- **已有**（≥2 处）→ 改它，别再造一个；

## 八、闭架（2026-11-11 落地）

> 交接 2026-11-11-0255 的图书馆定稿：**条目/典藏一个月不用 → 闭架；闭架被用到 → 条目；闭架可查、不优先。**
> 真图书馆的三线，到这里才真的会动。

| 事 | 在哪 | 怎么做 |
|---|---|---|
| 判定"该关" | `lib/library-shelf.js` `planDemotion` | 整份文件里**每一条**的 `at` 都早于 30 天前才算过期；混着新条的整份留着（不拆文件） |
| 真搬 | `demoteStale` / `demoteDaily` | 在用的文件整份挪到 `library/闭架/<年-月>/<类别>/<日>.jsonl`；桶名 = 搬进去那天所在的月 |
| 自动发生 | `lib/body-loop.js`（心跳） | 一天最多搬一次；搬了写 `library/meta/closed-state.json` 与 `closed-log.jsonl` |
| 查 | `libraryLookup` | 顺序仍是 在用 → 手抄本 → **闭架**；只在前两层都没结果时才翻，命中带 `zone:'闭架'` |
| 搬回 | `revive` / `library-closed.mjs revive` | 显式命令；目标已存在就换序号并存（两份都在，谁也不覆盖） |

命令：

```bash
node dsh-yushen-twins/scripts/library-closed.mjs stats              # 各层几本、闭架按月几个、下批到期几份
node dsh-yushen-twins/scripts/library-closed.mjs plan --days 30     # 只算不动：哪些文件该关
node dsh-yushen-twins/scripts/library-closed.mjs demote --yes       # 真搬（不带 --yes 一律 dry）
node dsh-yushen-twins/scripts/library-closed.mjs revive 知识/2026-10-01.jsonl
node dsh-yushen-twins/scripts/library-closed.mjs lookup 关键词
```

三条边界（测试里钉着）：

1. **只搬不删**：搬前搬后 sha1 一致，正文一个字不改；
2. **不优先**：闭架永远排在 在用/手抄本 后面，不许挤掉新条目；
3. **读的时候不写**：查闭架不会顺手把文件搬回来，搬回要显式 `revive`。

已知近似：现在没有"这一条被用过"的逐条痕迹，所以"一个月不用"暂时用条目自己的时间（`at`）代替；
等借阅反馈接到条目上，应改成读 `lastUsedAt`。
