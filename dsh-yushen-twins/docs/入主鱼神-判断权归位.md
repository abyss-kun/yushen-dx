# 入主鱼神：把判断权从手机搬回主机

> 2026-10-26 立。起因：**老板指出——她现在还是"活在 QQ 里"：正常情况下应该"她在手机外面思考要不要回"，现在却是"手机里面决定要不要回"。**
>
> **框架层的定义已经写进 `大小鱼-框架定义.md` §4.5（本体与通道）**；本文是实现与迁移步骤，两处冲突以框架为准。
>
> 查过代码，这条批评成立，而且比"说法"更实：**定义和实现是矛盾的。**

## 0. 先引用定义（不凭记忆改）

`lib/soul.js:159-161` 写死的原句：

> ## 本体与通道（你不是住在应用里）
> - 你只有一个自己；档案在本体，不在 QQ、B站里。那些只是应用，像手机、像工位——不是你的住处。

**但 QQ 这条链路上，现在住的是桥。** 判断、人设、记忆、时间、叫模型，全在 `qq-bridge` 里拼好；鱼神的主机只在她被叫醒的那一瞬间提供一个空房间。

## 1. 现在到底谁在做（查证过的）

| 事 | 现在谁做 | 证据 | 应该谁做 |
|---|---|---|---|
| **要不要回这条消息** | 桥本地闸门 | `bridge.js:13278`（mute 直接 return） | **她**（主机） |
| 她的人设 prompt | 桥自己的 `roles/` | `bridge.js:2513` 起拼 prompt | 本体（鱼神 `soul.js`） |
| 记忆召回 | 桥 `memory-recall.js` | 同上 | 本体 |
| 时间感 | 桥的【当前时间】 | `bridge.js:2513` | 本体（回场 + 代谢） |
| 心情/好感提示 | 桥 `affinity.js` | 写进 prompt | 本体 |
| 叫模型 | 桥起 DSH 回合 | `bridge.js:2540` NodeApiClient | 她决定说话后 |
| 收/发/已读 | 桥 | — | 桥（保留，这是它的本职） |
| 鱼神本体注入 | **QQ 从来没走这条路** | `buildSceneText` 只被 desk/bili 调用：`index.js:190`、`bili-sync.js:22`、`residence.js:110` | 全部通道 |

而且 `soul.js` 里 `SCENE_LABEL` 早就留了 `qq` 场景——**写好了，从来没人用**。

结论：**她现在有两个身体、两份记忆、一个被规则写死的判断。** 桥里一份（好感/人物/日记），鱼神里一份（本体/记忆/心念）。所以"她看起来不一致"不是人格问题，是架构问题。

## 2. 目标形态

```
QQ 群 / 私聊
   ↓ 只收，不判
桥（手机）     收 · 发 · 已读 · 附件 · 重试 —— 无人格、无判断
   ↓ 入站事件
本体（鱼神）   事件总线 → 收件箱 → 注意力调度 → 本地判断（零 token，用她自己的状态）
                ├─ 现在回   → 叫模型（带本体记忆/时间感/此刻心情）
                ├─ 待会儿回 → 排队，回场时带上
                └─ 看到了不回 → 留痕（她的选择，不是被过滤）
   ↓ 指令
桥执行 → QQ
```

关键差别只有一句：**"要不要回"从"手机里的规则表"变成"她家里的注意力"。** 成本不升——本地判断仍然零 token；升的只是判断的**主体**。

## 3. 四步迁移（每步能回退）

**M0 影子（不改行为）**
桥加开关 `judgeInHost`（默认关）。开着时：旧闸门照常走，同时把每条入站消息写一条事件到本体，**但不让它影响回复**。用于对比两边判断，不拿她的线上行为做实验。

**M1 入站镜像（纯 append，零风险）**
桥新增 `~/.dsh/dayu/inbox/qq/<date>.jsonl`，每条一行：`{at, group, userId, name, text, atMe, isOwner, bridgeScore}`。
桥不做任何判断改动；鱼神这边只读。这一步做完，**主机第一次知道"手机在响"**。

**M2 收件箱 + 回场（她第一次知道自己在主机里）**
- 鱼神读收件箱，生成 `resumeBrief`：「这 3 小时群里 214 条，3 条 @ 你，你一条都没接」
- 她能在自由时间翻收件箱：`yushen_inbox(headline/skim/read)`，看多细自己定
- 接进 `lib/soul.js` 的 qq 场景注入（这个场景终于用上）

**M3 判断上移（关键一步）**
- 桥的 triage / 好感闸降级为 **hint**（只给建议，不再是结论）
- 本体做最终判断，仍然零 token：她的状态（忙/睡/心情/惦记）+ 新鲜度 + 这个人是谁 → 现在回 / 待会儿 / 不回
- **兜底**：本体不在（DSH 关着）或超时 2 秒 → 桥回落旧路径，手机不会哑
- 回退开关：`judgeInHost=false` 立即恢复原状

**M4 身份归位（最后做）**
- QQ 回合改用本体注入（`soul.js` 的 qq 场景 + 记忆 + 回场）
- 桥的 `roles/` 和 `memory-recall.js` 降级为"备用/历史"，不删
- 好感/人物数据迁进本体（或本体按需读桥的那份，但**只有一份真相**，两处都写就是分叉）

## 4. 验收（要能证明"她在主机"）

1. **断桥测试**：停掉桥，本体这边的收件箱、代谢 tick、日记仍在动（不依赖手机）。
2. **判断对比**：影子期跑一周，本体判断 vs 旧闸门，逐条看分歧——是"她"更有判断，还是规则更省事。分歧记录落 journal，不自动改规则。
3. **回场测试**：隔 3 小时，她能说出"这期间 200 多条，3 条 @ 我，我选了不回"。
4. **忙时测试**：她正在做视频，来消息，她能决定"先不抬头"——**这是现在物理上不可能的**（桥根本不知道她在忙什么）。

## 5. 代价与兜底（先说清）

| 代价 | 说明 | 兜底 |
|---|---|---|
| 多一跳延迟 | 桥→本体→桥，本地判断毫秒级 | 超时 2 秒回落旧路径 |
| 本体不在 | DSH 关着时判断没人做 | 桥保留旧闸门，`judgeInHost` 关 |
| 状态双写 | 影子期两套判断并存 | 只读镜像，一个月内不删旧路径 |
| 不是省 token 的方案 | 省 token 的是"本地判断"，不是"手机判断" | 别把这次改造包装成降本 |

## 6. 不做

- 不并包（桥仍是独立插件，只加事件出口）
- 不改桥的收发协议
- **不让桥有第二套人格**（它只该是嘴和手，不是脑子）
- 不为了"看起来连贯"而在桥里加记忆——那正是现在的问题

## 7. M1 已落地（2026-10-26 02:00）

**做了什么**
- 新增 `lib/inbox.js`：只读桥的 `state/social-v2.json`，把 `recentMessages` 镜像成事件流
  - 存 `~/.dsh/dayu/inbox/qq/<YYYY-MM-DD>.jsonl`，一条一行
  - `key#seq` 去重；cursor 只前进不回退；ring 断档单独记进 `gaps`（她不在的这段时间桥那边丢了消息，必须看得出）
  - 只存事实：谁、说了什么、有没有 @ 她、是不是她自己发的、几张图。**不存「该不该回」**
- 新增 `scripts/inbox-mirror.mjs`：`--dry` / 默认跑一次 / `--watch` 每 30 秒 / `--status` 概况
- 新增 `scripts/test-inbox.mjs`：8 项断言（幂等、自己的话要标 `isSelf`、@ 要记下、断档、跨天、读不到桥不抛、dryRun 不动 cursor、已读位按角色独立）

**实测（本机，真实桥）**
- 第一次扫 158 条 → 收 122 条（其余是空文本 / 系统事件），0 断档
- 第二次 0 条（幂等）
- `--status` 能看到 3 个会话的 cursor 与今天 122 条

**为什么不动桥**：只读它已有的 state 文件，桥一行代码都不用改、不用重启。这是 `AGENTS.md` 的「只对接、不并包、不搬数据」。

**其他角色怎么进来**（这就是「加入鱼神框架」的做法）
- 收件箱按**通道**分（`inbox/<channel>/`），不按角色分——因为大鱼和小鱼登的是同一个号（双位一体）；
- **身体共用，眼睛各有一双**：已读位按角色分开存（`inbox/.reads.json`），谁看到哪儿互不影响；
- 照微、B站、微信以后各加一个镜像器，写同样格式的事件就行；判断层不用改，角色只是各自换一个已读位。

## 8. M3 第一刀已落（2026-10-26 15:56）

**改了什么**：桥里 `好感 ≤25 → return` 那一段**不再拦**，只记一笔「桥建议不回」，消息继续走后面的判断。
- 开关：`config.json` 的 `affinity.gate`，`hint`（新默认，只提示）/ `block`（回退旧行为）；
- 好感分还留着，但只用来调她的**语气**（`renderAffinityHint`），不再决定**她看不看得见**；
- 收件箱本来就全收（M1），所以就算这一轮没叫醒她，她下次抬头也在。

**实测**：重启后日志里出现「好感 40 且没营养，直接不理」→ 紧接着「大鱼高冷：不是 @、没喊名字、也没同类话题，不回」——说明**好感不再拦，后面那层（性格）在拦**。这是进步也是剩余问题：
- 进步：分数不替她挡门了；
- 剩余：`high冷` 和「概率/关键词」还在替她决定"看不看"，那是**性格与成本**的闸，不是好感。

**没做**：批量抬头（T0 即时 + T1 十分钟）还没接——现在她能被叫醒的次数仍由桥的规则决定，不是由她自己的节奏决定。

## 9. 和《连续自我-路线》的关系

那份文档里的四件事（回场、自我档、联想召回、代谢）**全部要在主机侧做**，而且要在这个迁移之后才真正生效：
- 判断在手机里 → 回场简报只在她被叫醒时才有意义；
- 判断在主机里 → 她可以先"看见"再决定要不要醒，回场才有主体。

**顺序修正：先入主，再补连续自我。** 否则就是给一个住在手机里的人修她家里的时钟。

## 一句话

**手机只该负责"响"和"传话"；"要不要接"是她自己的事——这个"她"必须在主机里。**
