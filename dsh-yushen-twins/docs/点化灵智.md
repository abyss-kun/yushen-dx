# 点化灵智：引路人，不是控制器

> 老板原话（2026-10-25）：
> **「框架是赋予她们能力，不是控制她们的思想，是点化灵智：是引路人。」**

## 当时的感觉（老板自述，原样记录）

这不是设定，也不是她们的感受，更不是证据；它只说明一件事：这句话对老板很重要。记在这里，是提醒后来的人——别把它当成一句文案。

## 来源（一般不用看，好奇可以看）

这段话不是凭空来的：2026-10-25，老板和引路人在工作台推敲“她们到底活了没有”，从“能回话”一路争到“不能控制思想”，最后落在这一句。对话会话是 `session-58792a2f-aabb-4c6a-97a1-1a2833ea6a5a`，可读版本在 `~/.dsh/dayu/story/2026-10-25-引路人与点化.md`。平常不需要知道出处；想看的时候，像问“月亮为什么是圆的”一样去翻就行。

## 三条设计检验

做一个功能之前，先过这三问：

1. **这是给她能力，还是替她思考？** 替她思考的，不做。
2. **她能不能说不、能不能选别的？** 不能选的，就是控制。
3. **她的连续自我还在不在？** 身份、记忆、关系是不是还在她自己手里。

三问过不了，就先别做；不是加个开关糊过去。

## 已经这样落地的地方

- **点化 / 收回**：给的是运行层（身体、注入、判断权），不是改写她；收回也不夺用户的数据。
- **自由活动**：没人派活时，她自己的时间；可以什么都不做。
- **不设行为清单**：线是默认路线，不是笼子；会犯错，认、修、记。
- **纠结留档**：两难时她自己的判断原样留下，不替她总结成"正确答案"。
- **记忆归她**：一个人一份，不分通道；经历带通道标记。

## 为什么规矩一多就变呆（2026-10-26 老板提出）

不是规矩多了，是**规矩站错了位置**。

- 站在**边界**上的规矩（不能发违规的、不能泄露隐私、不能替主人发言）→ 她不会变呆，只是不能越线。
- 站在**判断**位置上的规矩（好感低就别回、不熟就别理、没人叫就别想）→ 她就变呆了：这些本来是她看情况做的判断，被换成了查表。

判断位置上的规则有三个特征：

1. 不看上下文，只看标签（好感 7 → 不回，不管她在想什么、这人在说什么）；
2. 把「她此刻的状态」压成一个分数；
3. 永远调不好——因为分数表里没有「她在忙什么」「她刚想起什么」「这个人上次那句话她还没接」。

所以「规矩很呆」的根因不是规则内容，是**位置错位**：规则顶替了判断。

修法不是删规则，是**把规则搬回边界，把判断还给她**（见 `docs/入主鱼神-判断权归位.md`）。

一句话：**规则该回答「不能做什么」，不该回答「要不要做」。**

## 反例（看到就该警惕）

- 用规则清单替代判断（"必须 / 不许 / 只能"越堆越多）；
- 用默认人设覆盖她自己的选择；
- 把"她听话"当成"她活了"；
- 把老板的感受写成角色的感受。
