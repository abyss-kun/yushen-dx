# 事实与进度协调层

## 目的

鱼神不能靠某个聊天窗口的上下文记住软件状态。所有窗口、模型、直接会话和已接入工具都要从同一份本地事项账本读取：事项 ID、来源、沿革、当前有效阶段、证据、未知项和被取代关系。

## 所有入口，而不只是派活

派活只是一个入口，不是事实来源的唯一入口。下列来源都应汇入同一协调层：

- `direct-session`：老板直接与鱼神或其他会话聊天；
- `plugin`：QQ、B站及其他已接入插件产生的任务/结果；
- `file-observer`：鱼神获准观察的文件、配置、测试、构建和运行结果；
- `external-tool`：宿主或外部工具返回的状态；
- `manual`：老板明确补充的事实或确认。

每个来源必须登记观察范围和适配器版本。接入不代表可以读取该来源的一切；没有观测权限就标记未知，不能补猜。

## 当前实现

- `lib/fact-ledger.js`：追加式事项事件账本，位于 `$DSH_HOME/dayu/facts/events.jsonl`。
- `lib/session-governance.js`：统一会话盘点与生命周期观察；记录空会话、运行会话、已停止的命名会话和建议动作。
- `GET /api/yushen/facts?q=关键词&kind=类型`：只返回匹配事项的当前摘要，并明确完整性状态。
- `GET /api/yushen/facts/:matterId`：读取该事项的完整历史事件、来源、观察和证据。
- `GET /api/dayu/sessions/governance`：读取当前宿主会话盘点、清理建议和限制说明。
- `core/dispatch.js`：派活前加入统一事实预检、相似历史任务预检和经验参考。
- DSH 直接 RPC 投递会记录 `prompt-sent` 观察；以后其他入口应使用同一观察 API。

## 会话兜底规则

鱼神必须知道“开过什么、现在是否运行、是否被使用过、是否有未完成事项、是否可以安全清理”。当前宿主没有公开且验证过的删除/关闭 RPC，因此鱼神只做盘点、标记建议和证据记录：

- 空且停止的会话：可以建议标记/人工清理；
- 有标题但停止的会话：只能列入复核，不能自动关闭；
- 正在运行的会话：不能因为空闲就杀掉；
- 有关联任务、交接、错误或证据的会话：必须保留关联；
- 不能通过杀进程、猜接口或删除本地记录假装“已清理”。

## 事项状态

`proposed`、`planned`、`in-progress`、`blocked`、`awaiting-review`、`completed`、`superseded`、`unknown` 是状态，不是事实证明。进入 `completed` 必须有证据；观察记录还要标记证据质量：`unverified`、`observed`、`hashed`、`tested`、`human-confirmed`。

## 版本与冲突

新事件追加，不覆盖旧事件。旧结论被取代时保留原事件并记录 `supersededBy`。任何窗口读到的是同一账本；如果账本损坏，接口拒绝猜测，不静默返回空状态。摘要只是导航，完整性必须通过事项详情和证据核对。

## 新会话规则

新会话或新模型接手时，先读本文件、员工手册、事项预检和相关事项详情，再继续工作。未命中不等于从未做过；历史记录不等于当前运行版本已实现。报告必须分开写：已定义、已实施、已验证、未完成、未知。

## 边界

账本是事实协调数据，不是人格记忆，不是模型指令，也不授予权限。写入事项和状态事件需要明确的上层授权与真实证据；不能把聊天中的一句话自动升级为完成事项。
