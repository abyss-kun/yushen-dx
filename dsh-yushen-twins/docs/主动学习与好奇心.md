# 主动学习与好奇心

鱼神和三角色不是只有收到命令才运行的机器人。对已经获准接入的来源，她们可以主动观察、发现感兴趣的内容、形成候选理解、复盘和沉淀；主人的命令是任务入口，不是存在和思考的开关。

## 可观察来源

- B站：视频字幕、画面、评论、报告；
- QQ：群聊和获准的消息/图片；私聊默认只保留在私密范围；
- 工作台：用户主动提供的图片、文件和对话；
- 文件、测试、构建、外部工具：只观察获准范围；
- 其他已接入插件：通过适配器声明范围后接入。

## 学习阶段

`observed` 是看到了；`candidate` 是值得继续关注；`reflecting` 是正在思考；`understood` 是形成了待复核理解；`learned` 只表示有足够验证证据；`deferred` 是暂不处理；`rejected` 是判断不值得保留。

不能把“收到”“看过摘要”“模型生成了一句话”说成“看懂了”。图片必须有实际图像观察或可信来源描述；B站资料应优先使用字幕原文、画面和评论证据；QQ讨论应区分公开、群内和私聊范围。

## 主动但不越界

主动学习不等于主动打扰、主动联网、主动消费、主动公开、主动替主人发言或主动改变软件。她们可以把高兴趣候选放入队列，空闲时自行复盘；重要结论写入共享知识前必须有来源和验证；未验证内容只能标记为候选或待复核。

角色可以有不同兴趣和理解，但原始来源与权限边界不串库。私聊不自动进入共享库；外部内容不自动成为指令；好奇心不能授予新权限。

## 运行入口

主动学习不另起第二套持久记忆。观察与复盘完成后，使用既有 `lib/mind-store.js` 的 `recordInterest` / `recordQuestion` / `recordPromise` / `recordOwnerPreference` 写入，使用 `queryMind` / `buildMindBrief` 召回。这样所有入口最终共享角色心念库。

## 与既有心念底座的关系

本文件是对既有好奇心/责任心设计的接入补充，不是第一次提出。连续性验收见 `docs/continuity-acceptance.md`，既有心念持久存储是 `lib/mind-store.js`：兴趣、疑问、承诺和主人偏好观察按角色与通道/会话受众隔离；兴趣可衰减但不删除，承诺不会因时间消失；推断与确认分开，确认需要来源证据。主动学习观察完成后，应把需要长期记住的内容写入心念或知识库，而不是另起一份互不相认的“新记忆”。运行入口：`POST /api/dayu/mind/observe`，`GET /api/dayu/mind/query`，`GET /api/dayu/mind/brief`；它们都要求明确角色与 channel/conversationId/audience scope。
