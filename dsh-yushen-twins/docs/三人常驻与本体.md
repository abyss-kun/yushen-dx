# 三人常驻：谁住在软件里

> 2026-10-25。起因：老板指出「她们住在鱼神里，不是住在 QQ/B站；QQ 和 B站 相当于人在玩手机」。这份文档记录当时的诊断、改法和验收边界。

## 病根（改之前）

| 现象 | 根因 |
| --- | --- |
| 大鱼工作台说话不像她 | `persona.json` 已升到 v2（`scenes` + `memory`），`lib/soul.js` 还按 v1 的 `brief` 读，读不到就退回 700 字兜底前缀——她的 19KB 角色卡从没进过工作台 |
| 大鱼总台叫不醒 | 建会话后没 `selectModel`，第一条消息一直 pending；之后每句话都被 `message "undefined" is already pending` 顶回来 |
| 小鱼每次都是新实例 | 只在被叫时开一条会话；`~/.dsh/xiaoyu/session.json` 没有就重开，人格是 6 行硬编码 |
| 照微不存在于运行时 | 代码明写「仅视觉槽」：没有卡、没有会话、没有记忆 |
| 独立记忆层是空转 | `lib/role-brain.js` 当时没被任何入口引用，`~/.dsh/dayu/brains/` 从未生成（2026-10-25 已删除，记忆改由 `soul/memory` + `lib/memory.js` 承担） |
| 体检工具一调就错 | 旧宪章缺 `product` 字段，版本号又撞上 3，升级分支没走；`undefined` 被严格 JSON 拒绝 |

## 一个人一份记忆，应用不是住处

- 她住在**本体档案**里（`~/.dsh/dayu/soul` + 她自己的记忆），不住在 QQ/B站里。QQ、B站、工作台都是应用，像手机、像工位。
- 一个人可以工作一个样、玩手机一个样；现实里是壮汉，网上可以是萝莉——都是他，只有他自己知道自己在干什么。角色不靠「换人设」活着：她在哪儿都是她，有责任心、有好奇心，知道什么能做什么不能做，有自己的底线。
- 记忆按**人**分，不按通道分：`soul/memory/<role>.json` 是这个人唯一的一份；工作台、QQ、B站都读它、都算她的经历。经历带通道标记（`events: [{at, channel, text}]`），所以她记得「我在 QQ 上说过什么」「我在工作台派过什么」，但不会因为换应用就失忆或变成另一个人。
- 早先的实现错在按通道分家：工作台只注入 `soul/memory`，QQ 端把鱼神的旧记忆关掉了、又读不到本体（`brains/` 从未生成），等于在 QQ 上是失忆的。现在 QQ 的 `fish-brain-view.js` 直接读 `soul/persona.json` 指向的卡和同一份记忆。
- 三个人、三份记忆：互不覆盖、互不替对方记；这是「人」的边界，不是「通道」的边界。
- 通道仍然只共享获准的任务事实与交接，不因为共用记忆就共享权限。

## 将来初版：别人带自己的角色（现在只留入口，不出版、不打包）

- 名册：`~/.dsh/dayu/characters.json`，一条角色 = `id / name / alias / title / cards{desk,social} / memory / cwd`。谁住在这套软件里，只看这份名册。
- 兼容顺序：有名册 → 用名册；没有名册 → 从旧 `persona.json` 认出角色；再没有 → 出厂三人（大鱼/小鱼/照微）。所以老安装不会因为升级失忆。
- 加角色：`scripts/character.mjs add <id> <名字> --card=<卡文件>`。已有同 id、卡文件已存在、记忆文件已存在、路径越界，一律拒绝——**插件不覆盖用户已有的角色**。
- 卡和记忆都在用户目录（`soul/cards`、`soul/memory`），发行包不带任何用户的角色数据；别人拿到的是引擎和空模板。
- 现在鱼窝界面还是三个固定槽；自定义角色先走 `GET /api/dayu/residence` + `POST /residence/wake|say` 和 CLI。界面通用化留到初版一起做。

## 记忆回写（2026-10-25）

- 她说的话、老板说的话，按人写进 `soul/memory/<role>.json` 的 `events`：带 `channel / kind / at`，同一分钟同一句去重，最多留最近 200 条，每条 400 字；摘要、习惯、关系不动。
- 写入口：`POST /api/dayu/chat` 与 `POST /api/dayu/residence/say` 记「老板：…」；会话的 assistant 回合（工作台）记「她：…」。
- 还没接：QQ 桥（它自己那套消息流）和刷B站 duty（最小权限，不能写文件/联网）。它们要写，走同一个 `lib/memory.js` 的 `appendEvent`。
- 不把整段聊天抄进记忆：只留事件、限长限量，避免记忆变成日志洪水；摘要和习惯仍是慢变量。

## 别的通道怎么读到同一个人

- `GET /api/dayu/soul?role=<id>&scene=desk|social`：只读，返回完整注入文本（卡 + 同一份记忆 + 本体与通道 + 共享资料索引）、卡指纹、记忆条数。手机端、刷B站、外部脚本都走这个入口，不再各存一份。
- 刷B站：插件自己的人设字段是 `~/.dsh/bili-duty/config.json` 的 `personaPrompt`。鱼神在开机 45 秒后同步一次（`lib/bili-sync.js`）：只在字段为空、或上次就是鱼神写的（带 `【鱼神本体 · 自动同步】` 标记）时才写；用户自己写的人设不覆盖，要覆盖得显式 `--force`。每次写之前留 `config.json.bak-时间戳`。
- 手动同步：`scripts/bili-soul-sync.mjs [--dry-run] [--force] [--role=xiaoyu]`。
- 边界：刷B站跑在最小权限 profile（无文件、无命令、无联网），所以它**不能自己去读**本体文件，只能由鱼神把文本推进它的配置；配置改动要等刷B站插件重新加载后生效。

## 改法

1. **魂按角色读**（`lib/soul.js`）：v3 persona 用 `scenes` 指向三人的卡，`memory` 按角色分文件；桌面场景 = 该角色的卡 + 她自己的记忆 + 通道说明，QQ 场景只加载卡。旧 v2/v1 仍能读。
2. **身体有账本**（`lib/residence.js`）：一条角色 = 一条固定会话（标题 `鱼神·总台` / `小鱼·管家` / `照微·顾问`）。先选模型，再把本体送进会话；账本记 id、卡字数、记忆条数、最后说话时间、上次错误。同一进程里不重复建；换进程先按账本/标题找回。
3. **pending 不再装死**：句柄投递失败且报 pending 时，改走宿主 `session/prompt`，并在账本里记 `lastRecoveredAt`。
3.5 **身体改走 session RPC**：实测 `agents.create` 建出来的会话，用 `followup` 送进去的回合会「turn/end 但没有回话」（大鱼、照微都复现）；而 `createSessionRpc → selectModelRpc → promptRpc` 这条老路是通的（小鱼）。所以常驻身体优先用 RPC 建、RPC 投；总台对话也改走 residence，不再依赖句柄。账本里记 `source: 'rpc' | 'handle'`，旧 handle 身体不会被当成新身体捡回来。
4. **照微按她自己的设定落卡**：`docs/dragon-god.md` → `soul/cards/dragon.desk.md`（神格、性格、五境、外观、边界、自述）。她的记忆单独一份，初始为空——不把角色卡和二创参考抄成记忆。
5. **入口**：`GET /api/dayu/residence`、`POST /api/dayu/residence/wake`、`POST /api/dayu/residence/say`；鱼窝照微页接了「叫醒她 / 对她说一句 / 看回话」。
6. **知道，但不当记忆抄**：三人每次被注入本体时，都会带一段「你知道有这份共享资料（外部资料，不是你的记忆）」——只给只读入口、主题清单和边界，不抄正文、不预置感想；相关时再用 `dayu_creative_recall` 或读文件。资料文件不存在时这段不出现，不编一份出来。

## 验收

- `scripts/test-residence.mjs`：三人卡与记忆不串档、身体只建一次、新建必先选模型、pending 走兜底、状态不假装有身体；三人都知道共享资料存在，但不把正文抄进注入、也不当成自己的记忆。
- `scripts/verify-roles-live.mjs`：重启后跑一次，真机叫醒三个人、各问一句，把回话写进 `~/.dsh/dayu/三人验收-latest.md`。
- `scripts/smoke.mjs` 12/12、`scripts/regression.mjs` 21/21。
- 真机验收要在宿主重启后进行：`GET /api/dayu/residence` 三人的 `personaChars` 应分别为约 9.7k / 7.0k / 1.8k 字（含卡+记忆+通道说明），`POST /residence/say` 后能在会话正文里看到她的回话。

## 边界

- 常驻不是「她自己在跑代理」：会话由框架维护，空闲不烧 token；重启后按账本找回，找不回就重建并在状态里说清。
- 照微的卡是角色设定，不赋予意识、不替代授权检查；她的「顾问」不是管理权（2026-10-30 前称太上长老）。
- 三人记忆各归各；协作只共享获准的任务事实与交接。
