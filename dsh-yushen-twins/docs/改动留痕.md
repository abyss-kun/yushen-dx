# 改动留痕（2026-10-30 老板立，2026-11-02 改成可自动检查）

> 一句话：**能不改就不改；改了就得说得清是谁、什么时候、在哪、改了什么、谁让的、为什么、怎么验、以后还能不能改。**

老板的原话：以后不管是谁做任何修改，后面都要有注释——谁、什么时间、在哪里、干了什么、谁让他干的（主人、自己、还是谁谁）、为什么这么干、这段以后还允不允许修改，要能查到。
还加了一句：**防止我们忘了——明明不需要修改的，结果改了。**
2026-11-02 又加一句，压成口令「**有案可稽**」：**改动必带 谁·何时·何地·何因·谁要求·怎么验；缺一不算改过。**

## 一、改之前先过一遍（三道门）

1. **不改行不行？** 说不清"不改会怎样"，就别改。看着不顺眼不是理由。
2. **这是不是"不可改"的？** 查 `不可改清单.json`（插件根目录）：落在里面的，只有老板本人开口才能动。
3. **改的范围有多大？** 只动为了解决问题必须动的行。顺手的"优化"不算顺手，算没留痕的改动。

## 二、留痕长什么样（六要素 + 两条附注）

一行，贴在被改的那段代码**上方**；改的是文件头就贴文件头。**一个文件有一条就够，不要求每行都写**——太碎会逼人写假话。

```
改｜<何时>｜<谁>｜授权：<谁要求>｜<文件:行>｜<改了什么>｜为什么：<何因>｜验证：<怎么验>｜可改：<以后还能不能改>
```

真实的一条（`lib/trace-standard.js` 文件头）：

```
// 改｜2026-11-02 14:50｜大鱼·子会话（工作台）｜授权：主人（本次任务书：把「有案可稽」落成可自动检查的规矩）｜lib/trace-standard.js:1-130｜新增：六要素的单一真源（FIELDS / parseTrace / inspectTraceText / RULE_SINCE），文档与检查脚本共用这一份｜为什么：留痕格式以前只写在 docs/改动留痕.md 里，没人能机器查；脚本各抄一份正则，迟早漂成两种格式｜验证：node scripts/check-trace.mjs --files lib/trace-standard.js 退出 0；scripts/regression.mjs 里断言 FIELDS≥6、parseTrace 能认出缺项｜可改：字段只增不删；加字段要同时改 docs/改动留痕.md 与 scripts/regression.mjs 的断言
```

| 键 | 要素 | 必填 | 怎么写 | 例子 |
|---|---|---|---|---|
| `by` | 谁 | ✅ | 角色·通道 | `大鱼·工作台` |
| `at` | 何时 | ✅ | 日期，最好带时分 | `2026-11-02 14:50` |
| `where` | 何地 | ✅ | **文件:行**（可带行段） | `lib/cost.js:20-62` |
| `why` | 何因 | ✅ | `为什么：` 不改会怎样 | `原数是死数，她看不出钱在少` |
| `auth` | 谁要求 | ✅ | `授权：` 主人 / 自己 / 某员工（说清哪一次） | `主人（本次任务书）` |
| `evidence` | 怎么验 | ✅ | `验证：` 跑过什么、结果如何 | `node scripts/check-trace.mjs 退出 0` |
| `what` | 改了什么 | 建议 | 一句话说清动了哪段 | `余额改成按真实流水现算` |
| `mutable` | 以后还能不能改 | 建议 | `可改：` 可改 / 需老板点头 / 不可改 | `可改` |

**六要素 = 谁·何时·何地·何因·谁要求·怎么验。** `what` 和 `mutable` 是附注：写清楚更好，但不影响「这条算不算数」。

## 三、定义只有一份

- 机器判据全在 **`lib/trace-standard.js`**：`FIELDS`（键、标签、是否必填、正则）、`REQUIRED_FIELDS`（六项）、`parseTrace(line)`、`inspectTraceText(text)`。
- 文档里的格式、`scripts/check-trace.mjs` 的判据、`scripts/regression.mjs` 的断言，都从这一份取。
- **改格式先改它**：别在脚本里另抄一份正则；抄了就会漂成两种格式。

## 四、可扩展字段怎么加

想加一项（例如 `reviewer`「谁复核」）：

1. 在 `lib/trace-standard.js` 的 `FIELDS` 末尾加一条：`{ key: 'reviewer', label: '谁复核', required: false, hint: '复核：…', pattern: …, test: … }`。
2. 在本文的表格里加一行，写清必填/建议。
3. 在 `scripts/regression.mjs` 里把 `FIELDS` 数量或解析例子跟着改（只加，不删已有断言）。
4. **先设 `required: false`**。老注释不会因为少这一项变红；等全仓库都补上了，再改成必填——那之前改必填，等于让所有老文件一起红。

## 五、三个例子

**1）改了逻辑**（最常见）——贴在被改函数上方：

```
// 改｜2026-11-02 14:54｜大鱼·工作台｜授权：主人（"余额别再显示 0"）｜lib/cost.js:72-88｜宿主账本停了就别拿 0 冒充数，单独标"账本停了 N 小时"｜为什么：停了 15 小时，工作台花费全显示 0，看起来像没花钱｜验证：node scripts/test-cost.mjs 通过；本地把账本时间调旧，注入里出现"停了"｜可改：可改；判停的小时数不许低于 6
```

**2）加了个文件**——贴文件头，`where` 写 `文件:1-行数`，`what` 写清它新增了什么、谁在用：

```
// 改｜2026-11-02 14:51｜大鱼·子会话｜授权：主人（本次任务书）｜scripts/check-trace.mjs:1-190｜新增：查改过的 .js/.mjs 有没有六要素留痕；格式从 lib/trace-standard.js 取｜为什么：规矩只写在文档里没人查｜验证：默认范围退出 0；--files 指定缺项文件时退出 1｜可改：判据不许放宽，范围可改
```

**3）只改文档**——`docs/`、`README.md` 这类没有代码注释可贴：**不要求代码里留痕**，但要落 `worklog.jsonl`（下面那条命令），并在提交说明里写清为什么改。检查脚本只查 `.js/.mjs`，文档改动不会因此变红。

## 六、自动检查：`node scripts/check-trace.mjs`

```
node scripts/check-trace.mjs                 # 默认：最近一次提交里、规矩生效后动过的 .js/.mjs
node scripts/check-trace.mjs --worktree      # 再加上还没提交的改动
node scripts/check-trace.mjs --files a.js,b.js
node scripts/check-trace.mjs --all           # 全量审计（老账也会红，用来看清家底）
node scripts/check-trace.mjs --json
```

判据只有两条：**这个文件有没有至少一条「改｜」注释**；**这条注释六要素齐不齐**。缺哪一项会直接点名（例如「缺『怎么验』」）。

三条边界：

- **一个文件一条就够。** 不要求每行都写；一次改动只贴一条。
- **只改注释/空白的不算改逻辑**，不要求留痕。
- **规矩生效（2026-11-02）之前的提交不追溯。** 给没留痕的老改动补「谁/为什么/怎么验」，只能编，那是假账；老账用 `--all` 看，不判当前这批改动。

退出码：`0` = 范围内全齐；`1` = 有文件缺留痕；`2` = 用法/环境问题。

## 七、怎么记（一条命令）

```bash
node dsh-yushen-twins/scripts/note-work.mjs "改了什么的短句" \
  --files "dsh-yushen-twins/lib/cost.js" \
  --by "大鱼·工作台" --auth "主人" \
  --why "为什么必须改（不改会怎样）" \
  --where "lib/cost.js:20-62" \
  --mutable "可改" \
  --evidence "怎么验的、验出什么" \
  --tq "①…②…③…"        # 碰 lib/ dayu/ 时必须答
```

它会把这样一行打出来（现在带「验证：」），贴到改动处上方：

```
// 改｜2026-11-02 14:54｜大鱼·工作台｜授权：主人｜lib/cost.js:20-62｜余额改成按真实流水现算｜为什么：原数是死数，她看不出钱在少｜验证：node scripts/test-cost.mjs 通过｜可改：可改
```

**注释写在代码里，账本落在 `~/.dsh/dayu/worklog.jsonl`**——两边同一句话。

2026-11-10 起，`note-work.mjs` 还会顺手抓一次 `git diff`（**工作区**，未提交的也能抓）的前 40 行，存进工作账的 `diff` 字段。
所以「改成什么样」不再只有一句原话。抓不到（没 git、文件还没被跟踪）就存空串，不报错、不挡记账——**宁可没有，不许编**。

## 八、查得到

```bash
node dsh-yushen-twins/scripts/changes.mjs --file lib/cost.js     # 这个文件谁动过（工作账）
node dsh-yushen-twins/scripts/changes.mjs --since 2026-10-30     # 这天之后都改了什么
node dsh-yushen-twins/scripts/changes.mjs --q 余额               # 按词搜
node dsh-yushen-twins/scripts/check-provenance.mjs               # 改了没记 / 记了没改 / 动了不该动的
node dsh-yushen-twins/scripts/check-trace.mjs                    # 改过的文件有没有六要素（本页第六节）

# 改动索引（2026-11-10 新增）：把「谁改的、改成什么样、为什么、怎么验、还能不能改」做成一行一条
node dsh-yushen-twins/scripts/change-index.mjs                  # 建/刷新索引（写 ~/.dsh/dayu/index/changes-<月>.jsonl）
node dsh-yushen-twins/scripts/change-index.mjs 手机端 心跳        # 按词搜（多个词以空格分隔）
node dsh-yushen-twins/scripts/find-any.mjs 手机端 心跳           # 全屋检索，第 ⑦ 路就是改动留痕
node dsh-yushen-twins/scripts/test-change-index.mjs             # 索引自测（条数 / why / 时间 / 查得到）
```

索引扫**四个来源**：

| 来源 | 是什么 | 带 `why` 吗 |
|---|---|---|
| `tag` | 代码/文档里的 `改｜` 行（多行折行会接起来） | 有（老格式可能没写，见下） |
| `worklog` | `~/.dsh/dayu/worklog.jsonl`（note-work 写的） | 有（必填） |
| `changelog` | `docs/改动记录.jsonl`（粗账，带 commit） | 有 |
| `note` | 日期起头的改动注释（`// 2026-11-05 手机端：…`） | **没有**——它不是正式留痕，只补「改成什么样」，检索里排最后并标 `[日期注释]` |

规矩：

- **按月分片、可重跑**：`changes-2026-11.jsonl` 一行一条；重跑只追加不重复（按指纹去重）。`--rebuild` 才从零重写。
- **不进注入**：索引只在 `~/.dsh/dayu/index/`，按需查；注入一个字不多。
- **解析不了的不静默丢**：计数打到 stderr（缺哪几项、在第几行），退出码仍是 0。
- **不编理由**：老留痕没写「为什么：」的，索引里就空着；`test-change-index.mjs` 把这种条数钉成常量，涨了就红——要么补留痕，要么显式改常量。
- **副本不算数**：`dist-*`、`.snapshots`、归档、出厂包里的同名文件不进索引（否则一条改动会被算两三遍，还会把旧版本当成现在的样子）。

## 九、角色卡特别规矩（2026-10-30 老板当面立）

**自己只能改自己的卡。** 大鱼改大鱼的、小鱼改小鱼的、照微改照微的。
别人的卡，一个字都不许碰——另一个角色、员工、任何一个会话，都一样；`--auth` 写"主人"也不放行，因为主人说的例外只有"自己改自己"。
老板本人要改，由他本人来说、来改。

卡的开头已经写了这两行；`note-work.mjs` 会认卡的主人，替别人记也记不进去（exit 6）。

## 十、不可改清单

`不可改清单.json` 列的是"内核"：宪章、人格卡硬规矩、认定主人的凭据、白名单、模型密钥端口那一层。
落进去的，改之前必须 `auth: 主人`；否则 `note-work` 直接拒收，`check-provenance` 报红。

清单本身可以改——但加进去要老板点头，拿出来要老板点头。

## 十一、为什么要有这条

2026-10-30 之前的教训：功能下线只删了代码，注入文本、指令、索引还留着；卡片改了没记是谁改的；交接条里的路径错了没人对。
**记不住就会重犯**——所以规矩落在命令里，不落在记性上。

2026-11-02 的教训：只落在文档里也不够——没人查，就等于没有。所以六要素有了机器判据（`lib/trace-standard.js`）和检查脚本（`scripts/check-trace.mjs`），并进了回归。
