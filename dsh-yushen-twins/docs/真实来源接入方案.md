# 真实来源接入方案（补充既有心念，不替角色思考）

状态：QQ事实/同会话召回已接入；B站来源边界适配器已在插件本地完成但尚未接真实B站回合；QQ/B站到心念的生产写回尚未宣称上线。

## 核心原则

这不是第二套记忆，也不是把聊天自动总结成人格。接入链分成四层：

1. **来源事实层**：适配器保存原文、来源通道、会话ID、受众、消息ID、说话人和媒体引用。事实可去重、可回看，但不自动产生兴趣/疑问。
2. **会话召回层**：只按完整 scope（channel + conversationId + audience）召回当前会话相关事实；没有 scope 就拒绝。角色相同不等于受众相同。
3. **角色选择层**：把有限的事实交给当前角色。角色可查询、可记兴趣、可记疑问，也可以不记、延后、拒绝；写回只能发生在角色明确选择之后。
4. **既有心念层**：继续使用 `lib/mind-store.js` 的 interest/question/promise/owner_preference，不新增学习账本。观察默认 `inferred`；没有确认依据不能写 confirmed。

## 不做的事

- 不把第一句回复写成固定人格台词；桥只提供事实，是否报身份由角色决定。
- 不用“名字/关键词”规则替代角色判断；明确 @ 别人可以作为安全的唤醒节省边界，不是意识判断。
- 不将旧 `persona.json` 无 scope 摘要塞进QQ群聊。
- 不让管理 API 请求体自报 role/scope 变成可信身份。
- 不从图片/视频标题自动推断兴趣；没有角色选择就只留来源事实。
- 不以接口存在、fixture、单测或服务探活代替真实角色回合验收。

## 上线验收顺序

1. QQ先做“原始事实→当前会话召回”的真实回合；已完成代码接缝，仍需重启后的真实消息证据。
2. 在QQ当前角色真实回合中，由角色自行选择记兴趣/疑问或不记；验证写入既有mind-store，scope与source可回查。
3. B站先用已安装工具的真实字幕/评论/视频或画面结果生成来源事件，再让角色选择；不把刷轮报告自动等同于角色心念。
4. 用另一群、QQ私聊、B站公开视频/评论/私信和工作台查询哨兵，验证不串受众。
5. 每一步保留真实消息ID/会话范围/角色选择证据；没有证据的项目保持未验收。
