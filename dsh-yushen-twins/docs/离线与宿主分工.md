# 宿主与离线：谁干、干到什么程度、怎么停

> 2026-11-04 老板定。之前的说法把"跨进程覆盖"讲成了自然现象，那是错的：**覆盖的根子是分工不明确**。
> 一份数据只有一个写者；别人要动它，只能"请求"，不能自己下手。

## 一句话分工

- **宿主**：软件开着时跑的那个程序（你眼前的窗口）。对话、注入、回话、注册工具都在它里面。
- **离线**：另外拉起来的独立脚本，只读写硬盘文件，不碰界面。干完就退。

**宿主停了 = 下班。** 下班以后，除了明写的"收尾活"，别的都停；加班也要下班。

## 离线只分两类（不许有第三类）

### 一类：听差（宿主叫才干）

宿主叫一次，它干一次，干完就退。**宿主不叫，它不许自己开跑。**

| 谁 | 干什么 | 谁叫 |
|---|---|---|
| `maintenance.mjs` | 备份、归档、索引、巡视、清理、自愈 | 宿主每小时叫一次 |
| `memory-housekeeping.mjs` | 遗忘、记忆合并 | maintenance 叫 |
| `offline-ticks.mjs` | 账本结算、阶位重算、通道回写 | maintenance 叫 |
| `self-heal.mjs` / `weekly-patrol.mjs` / `recall-auto.mjs` | 自愈 / 体检 / 自主检索 | maintenance 叫 |
| 各种 `pack` / `check` / `build-*` | 打包、检查、建索引 | 人叫或 maintenance 叫 |

**规矩**：
- 不自己定闹钟，不自己循环；
- 有硬超时（到点自己退）；
- 干到一半宿主下班了 → **做完当前这一小步就退**，不接着干下一件。

### 二类：值夜（宿主不说，它自己能干）

**现在一个都没有。** 以后要加，必须同时满足：

1. 白名单里明写（谁、干什么、多久一次、最多干多久）；
2. 有小时/次数上限（不能无限再来）；
3. **宿主一下班就停**（不是"跑完这一轮"，是"看到下班就收手"）；
4. 出问题不影响宿主启动。

加不了这四条，就还是一类（听差），别给自己找"后台常驻"的理由。

## 下班怎么判

宿主每 60 秒写心跳 `~/.dsh/dayu/runtime/host-alive.json`。
- 维护每跑一步前看心跳：**断了（>5 分钟）就整轮收手**，一步不多做；
- 备份、清理、合并都不例外（数据没变不需要再备一份）。

## 崩溃与修复（关键）

1. **硬超时**：每个离线脚本进来就挂定时器（维护 30 分钟，其余 5~10 分钟），到点 `process.exit(0)` —— 自己退，不等别人杀；
2. **锁带 TTL**：`runtime/maintenance.lock` 记 `pid + at`，超过 40 分钟或 pid 已不在 = 僵死；
3. **宿主启动先清僵死锁**：`clearStaleMaintLock()` 在派发之前跑。一次崩溃留下的锁，不能让宿主再也起不来；
4. **离线不许持有宿主启动需要的东西**：唯一例外是备份目录，而它只读不锁；
5. **写文件只走 tmp + rename**：退在中间不会留下半个文件。

## 数据归属（写者唯一）

| 数据 | 唯一写者 | 别人怎么用 |
|---|---|---|
| 她自己的记忆 `soul/memory/*.json` | **本体**（`lib/memory.js`） | 离线只读、或经"请求"由本体写 |
| 清理/合并的结果 | 现在由 `memory-housekeeping` 直接写 → **违反本条**，改成"先把要删/要合的清单写出来，由本体执行"（**待做**） | — |
| 桥的流水 | 桥 | 本体只读 |
| 账本 | `lib/cost.js` | 离线调它算，不自己写文件 |
| 心跳 / 锁 / 状态 | 各自的主人 | 别人只读 |
