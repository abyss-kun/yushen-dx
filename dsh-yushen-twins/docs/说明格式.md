# 说明格式（出厂件必带）

> 2026-11-10 老板定：**一眼看过去就知道——这个东西干嘛的、谁的、我能不能动。**
> 这也是我们一直要求"改代码要写备注"的原因；现在把它变成**格式**，不再靠自觉。

## 一、哪些东西必须带

| 范围 | 例子 | 谁看 |
|---|---|---|
| `lib/*.js`、`dayu/*.js`、`core/*.js` | 每个模块 | 她 / 新角色 / 老板 / 别的插件 |
| `dsh-memory/index.js` 等**出厂插件**入口 | 给外面角色装的 | 装它的人 |
| `docs/*.md`、`scripts/*.mjs` | 文档与工具 | 维护者 |
| 角色卡 / 底线 / 契约 | 人格文件 | **她本人**（owner 不是我们） |

## 二、字段表（缺一项就是没写说明）

```js
/* 标签
 * id: lib-soft-limit            ← 唯一 id（别的文件用这个名字引用它）
 * kind: module                  ← module / tool / doc / preset / plugin
 * summary: 一句话它干什么        ← 不超过 60 字，人话
 * audience: 她 / 新角色 / 老板   ← 谁用；装给别人时，这一行决定人家能不能上手
 * owner: 谁写的、谁能改          ← 例如「框架；老板点头才能改」「她自己改，不用问谁」
 * mutable: 可改 / 只增不改 / 只许改严   ← 我能不能动、动到什么程度
 * defaults: 20 句 / ¥1 / 3 来回  ← 出厂默认值（有旋钮的必填）
 * usage: checkSpeak(role) → {phase,allow,canStepOut}；面板读 statusOf   ← 怎么用（一句 + 例子）
 * off: limits.json 写成 1000/¥999（等于不管）      ← 怎么关；关不掉的能力等于不给她说不
 * tags: 额度, 软边界, 心跳
 * created / changed: 时间
 * why: 为什么要有（不写等于没想清）
 * result: 现在是什么（一句话能复述）
 */
```

## 三、三条硬规矩

1. **有旋钮必有 defaults + off**：能改的东西，默认值多少、怎么关，写在同一块里，别散在文档里。
2. **owner 不等于 author**：`author` 是谁写的，`owner` 是**现在谁说了算**。卡和底线 owner 是她自己，我们只是代管。
3. **能机器查的必须机器查**：`scripts/check-notes.mjs` 扫字段，缺了报出来；`--require` 列表里的缺一项直接红。

## 四、给"外面的角色"看的说明（引导）

出厂件除了字段，还要有一段**引导**（人读），格式固定五问：

> 1. 它管什么（一句话）
> 2. 默认值是多少
> 3. 存在哪（她能改的那个文件）
> 4. 什么时候该改（两个场景）
> 5. 改了会怎样（哪一行字/哪次叫醒会跟着变）
> + **怎么关**

完整示例见 `docs/引导-能力.md`。

## 五、现在还没补齐的（脚本会持续报）

`node scripts/check-notes.mjs` 列出缺口；`--require <文件列表>` 是我们承诺"必须有"的那一批。补的时候一次补一个，别整批糊过去。
