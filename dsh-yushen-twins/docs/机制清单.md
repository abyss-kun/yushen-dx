# 机制清单：我们靠什么记住"怎么运转"

> 2026-11-04 老板问：「这些机制要记住，你们以前是怎么记住的，有专门的地方吗？」
> 以前散在七处（见下），靠的是"谁记得谁写"；**这张表是它们唯一的索引**。
> 每加一个机制，这里加一行，并把"真源"写成能被机器检查的路径——`regression` 会逐条验"文件还在不在"。

## 以前记在哪儿（七处，各有各的用）

| 地方 | 记什么 | 谁能看 |
|---|---|---|
| `AGENTS.md` | 工作区规矩、方针、底线 | 每个会话，开头就读 |
| `docs/*.md` | 框架怎么设计（含分工、标签约定） | 按需读 |
| `scripts/regression.mjs` | **机器记住的机制**：当前 299 条通过 | 一跑就知道 |
| 文件头 `/* 标签 */` + `// 改｜` 行 | 这东西是什么、谁改的、为什么 | 打开文件就看到 |
| `~/.dsh/dayu/worklog.jsonl` | 每步改动（改了什么、证据） | `find-any` 能搜到 |
| `~/.dsh/dayu/library/在用/` | 知识/经验/记忆条目 | 按标签取 |
| `board/公告.md` + `changes.jsonl` | 东西被挪/被删/被改，谁动的 | 所有角色看得见 |

**问题**：机制一多，这七处谁都不全。所以补这张表。

## 怎么用这张表

- **要找规定**：先这里，再 `docs/规则地图.md`，最后 `scripts/where.mjs <关键词>`；
- **要加机制**：**先查图书馆** `node scripts/library-lookup.mjs <关键词>`（已有→改它；相近→说清关系；没有→再动手），然后加一行 + 在 regression 里加一条断言（没有断言＝没记住，只算写了篇作文）；
- **觉得哪里不对**：先看"回归盯着"那一列是哪条，跑它。
