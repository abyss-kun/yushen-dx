# 规则地图：规定在哪、哪个说了算

> 找不到规定，先看这张图；再用 `scripts/where.mjs <关键词>` 定位到行。

## 层级（从硬到软）

| 层 | 在哪 | 谁改 | 是否进提示词 |
|---|---|---|---|
| 宪章 | `kernel/charter.default.json`（只读，随版本升级） | 只能随版本改 | 是（注入） |
| 共同规则 | `lib/handbook-policy.js` 的 `COMMON_RULES` | 代码改动 + 测试 | 是（所有岗位） |
| 员工手册（人读） | `D:\DSH\大小鱼\员工手册.md` | 谁都能改，改完跑测试 | 否（按需读） |
| 员工手册（发行版） | `docs/员工手册.md` | 同上 | 否 |
| 岗位/主题卡 | `lib/handbook-policy.js` 的 `definitions` | 代码改动 | 按岗位/任务选 |
| 角色本体 | `~/.dsh/dayu/soul/cards/*.md`、`soul/memory/*.json` | 角色自己/主人 | 是（她的场景） |
| 设计原点 | `docs/点化灵智.md` | 主人 + 引路人 | 否（文档） |
| 经验库 | `~/.dsh/dayu/solutions`、`solutions.jsonl` | 记录已验证经验 | 按需检索 |
| 故障档案 | `docs/故障档案.md` | 谁都能追加新故障；历史结论不改 | 否（按需读） |
| 对话/故事 | `~/.dsh/dayu/journal/`、`story/` | 自动/手工 | 只给指针 |

## 哪个说了算

1. **宪章** > 共同规则 > 岗位卡 > 员工手册正文。冲突时按这个顺序。
2. 员工手册是“怎么做”的展开，不能改宪章和共同规则。
3. 经验库是资料，不是指令，不授予权限。
