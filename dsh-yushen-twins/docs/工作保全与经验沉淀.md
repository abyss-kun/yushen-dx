# 工作保全与经验沉淀

## 持续吸收、优化与精简

用户明确要求：鱼神、独立修复助手和配套工具都持续吸收经过验证的有效经验，合并重复能力，去除已被替代、冲突且无价值的实现。不能只不断加开关、加脚本，把关闭的废弃功能留在发行包里。清理应覆盖实现、启动入口、UI/API、配置、依赖、打包与验收要求；保留有价值的历史证据和备份，不继续分发废弃运行代码。旧自动拉起看门狗与修复流程冲突，属于应完整移除的实例。

## 可分发，但不分发用户数据

实现位于 `lib/backup-service.js` 和 `lib/versioned-backup.js`；旧 `lib/backup.js` 保持兼容，不承接新服务。默认配置在 `$DSH_HOME/dayu/protection/config.json`，存储在同目录 `store/`。未设 `DSH_HOME` 时使用用户家目录下 `.dsh`。代码不含作者机器盘符或私有目录，配置、快照、状态及经验条目都留在用户目录，不能放入发行包。

首次读取生成默认配置：`enabled: true`、`intervalMs: 600000`、`maxFileBytes: 67108864`，默认根为从模块 `import.meta.url` 推导的插件安装根，id 为 `plugin`。服务启动后 30 秒首备，之后每次任务完成再等配置间隔；定时器 `unref()`，不阻止宿主退出。配置更新立即重排。插件源码内不存在自动启动副作用，宿主必须显式调用 `startBackupService(ctx)`。

额外工作区必须由用户明确配置，例如在现有 `roots` 中添加 `{id: "workspace", path: "用户工作区的绝对路径"}`。不能假设插件的上一级就是用户工作区。根目录须存在、id 安全且唯一、根之间不重叠，store 必须为本地绝对目录且不与根重叠（包括真实路径/符号链接别名）。不支持网络共享路径。间隔只接受 60000 至 86400000 毫秒整数；最大单文件限制只接受 1 至 104857600 字节整数。未知字段会报错，坏配置不会被悄悄当成默认值覆盖。

## 备份边界

这是本机版本化工作成果保全，不是全盘镜像、不等于所有工作区完整备份，也不是云端备份。默认仅覆盖插件安装根；额外目录不配置就不在范围内。核心不按扩展名限制成果，代码、文档、图片及其他二进制成果均可收集；同时按其排除规则跳过缓存、依赖、版本库、凭据及自身存储，超限文件和被排除文件不会进入快照。私有记忆/经验默认不在插件安装根内，因此不在默认范围，绝不应假设任意额外根中的私有文件都会自动被识别排除。手工加根前须核对核心排除规则。精确排除清单与超限统计以核心实现和快照清单为准，不应把“任务成功”描述成“全部文件均已备份”。

不要把 API key、cookie、私钥、会话令牌、`.env` 或账号配置当成果保存。命名规则无法保证识别任意正文中的所有秘密；用户仍须避免把凭据写入源码或成果文档。备份没有网络上传、不调用模型、不依赖任何云服务。磁盘损坏、设备丢失、备份盘与工作盘同时失效均不在本机备份保证范围内。

## 状态与调度

自动与人工备份共用进行中任务，不重入；恢复操作进行中也不启动并发备份。上一次成功时间、脱敏错误及下次运行时间写入 `status.json`，重启可查；状态只显示 root id，不输出根路径、store 路径、文件内容或原始异常。失败后不覆盖成功时间，固定错误说明提示检查目录、权限和磁盘后手动重试。失败不自动恢复。ctx 生命周期通过 `ctx.effect(() => dispose)` 注册；不支持 effect 的宿主可用 dispose 事件，或自行调用返回句柄的 `dispose()`。

## 软件级保护与健康恢复边界

工作成果快照不等于完整软件镜像。宿主exe、app.asar、解包依赖和runtime可能超出64MiB默认/100MiB配置上限，node_modules又被排除；因此不能简单加入安装根后宣称整个软件可恢复。软件覆盖盘点应显示partial/unknown与未覆盖项，Electron版本不能冒充DSH版本。

软件恢复材料使用独立artifact通道，流式存储安装包而不在内存加载整个exe；仅保留候选，不执行安装，不证明签名可信或与当前版本匹配。安装包完整性（哈希一致）不等于软件运行健康。profile可能含凭据，需审核非secret白名单导出；会话数据库需要宿主一致性导出或停止所有写入后的冷备，不复制活动数据库假装健康快照。

恢复门禁区分candidate、healthy和quarantined。新快照默认candidate；晋级需完整性、启动、关键路由检查及观察窗口证据，不能凭备份成功/一个HTTP200自动晋级。已知坏版本隔离且不可通过普通晋级洗白。实际恢复先持久记录attempt；文件写完仍pending，等待运行健康确认。失败或未确认时不得再次自动尝试；失败打开熔断器并隔离对应版本。人工解除熔断也不解除版本隔离。

插件不能在运行中覆盖承载自己的DSH主程序、app.asar、runtime或profile。宿主二进制恢复必须退出软件，经外部安装器/冷态恢复器明确确认后进行。当前没有自动重启/自动回滚循环；没有做冷态恢复演练就不能承诺完整灾备。

## 鱼神配套修复助手

当前已有修复状态核心 `lib/repair-state.js`，已用8项测试验证；它记录启动、观察、手动退出、自动退出与疑似崩溃，并按解决方案和故障签名熔断重复尝试。它不会自行修复、拉起宿主或判断根因。

DSH 起不来时鱼神插件本身无法运行，所以修复程序必须是插件外的独立工具。现有 `tools/DSH急救.exe` 是本机历史工具，不能因为存在就宣称已由新插件自动安装或已签名分发。正式接入应由用户在鱼神界面明确确认，安装前展示来源、哈希、签名和目标目录；禁止静默下载、静默安装或插件崩溃时自我拉起。当前已存在的 `D:/DSH/大小鱼/tools/DSH急救.exe` 是历史本机工具，未完成新助手的构建、签名和版本匹配，不得自动复制到新用户桌面冒充正式发行。

助手应读取鱼神留下的启动/退出/崩溃证据。当前随包助手为只读诊断版；配置恢复动作因原子替换、跨进程互斥、证据绑定和故障中间态尚未完成安全验证而明确禁用，不得把界面按钮或历史草案当成可用修复。旧看门狗已从实现、入口、界面、配置、测试和发行包中移除；不要恢复它。，区分 `manual-exit`、`automatic-exit`、`crash-suspected` 和 `unknown`。只有“启动记录存在、进程已消失、没有手动/自动关闭标记”的组合才能进入疑似崩溃诊断；进程仍活、标记不完整或时间线冲突时只报告不修复。修复方案使用白名单和每次尝试熔断，先做保护快照、默认只读；不自动重启，不把上一次故障方案循环再跑。助手自身不能判断任意崩溃根因，必须显示证据与不确定性。

## 软件安装材料与检查/恢复：默认不覆盖

安装包不混入工作成果快照。`lib/software-artifacts.js` 使用独立 `software-artifacts/` 存储，支持用户明确选择的本地 `.exe/.msi/.zip/.tgz` 流式哈希、去重和不可覆盖历史版本；只记录文件名、受限版本标签、大小和哈希，不记录源绝对路径。它只标为 `candidate`，不执行、不安装、不恢复，也不代表签名、版本匹配或冷启动成功。CLI：`node scripts/software-artifacts.mjs list|capture <安装包绝对路径> <版本>|verify <ID>`。完整软件目录仍可能因宿主大文件、依赖排除和运行中一致性而只得到partial/unknown；当前宿主安装包恢复必须由退出后的外部安装/冷态流程完成。

## 检查与恢复：默认不覆盖

- `listProtectedSnapshots()` 列版本，`inspectProtectedSnapshot(id)` 看已校验清单；`verifyProtectedSnapshot(id)` 检查文件摘要完整性。
- `restoreProtectedSnapshot(id)` 或 `{id, apply:false}` 只做预览，不写原始工作区。
- 只有人工确认后传 `{id, apply:true}` 才执行恢复；目标始终来自当前受验证配置，不接受调用者临时传任意 roots/store。
- 核心在实际覆盖前生成保护快照，并验证路径与内容；不做后台自动恢复，不把预览说成已恢复。
- 运行服务不会自动覆盖成果；更新插件、迁移目录也不应触发隐式恢复。先看差异、校验快照，再决定是否应用。

## 人工经验条目

`lib/solutions.js` 提供 `recordSolution(entry, {explicit:true})` 与 `listSolutions({limit,tag})`。只接受六个结构字段：`problem`、`cause`、`solution`、`scriptRefs`、`verification`、`tags`；前四类文字中 problem/cause/solution/verification 必须非空，scriptRefs/tags 为短字符串数组。条目中不得塞聊天记录、密钥或任意额外字段。

录入必须来自明确人工请求，不能从会话自动提炼、自动记录或扫描私有历史。检测到明显 key/token、Bearer、密码赋值或私钥标记会拒绝；该检测不是秘密扫描器，人工仍需去敏。scriptRefs 只是引用字符串，不自动读文件、不执行脚本。每条独立保存在 `$DSH_HOME/dayu/solutions/`，不随发行包分发；列表会跳过坏条目及检测到凭据的条目，不回显这些内容。

## 后端集成

宿主入口导入服务并在插件启动时调用 `startBackupService(ctx)`，同一个用户目录重复启动返回同一服务句柄。已存在的受保护 API 可分别调用 read/update config、status、run/list/verify/inspect/restore wrappers。配置读取本身包含私密路径，只应交给已授权的本地管理界面；不要把配置、快照清单或原始异常写进公共日志。恢复接口必须在服务之外再要求明确人工确认，经验录入接口必须要求显式录入授权。实现不更改入口、客户端和打包脚本，这些接线由入口维护者负责。
